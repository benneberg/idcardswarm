# Civitas AI: Strategic Design & Product Roadmap

This document outlines the target user personas, collaboration architecture, and core feature requirements for the **Civitas AI** (idCard Personas Swarm) management platform.

---

## 1. User Personas

Target individuals who interact with the agent ecosystem.

### A. The Swarm Architect (Technical Lead)
*   **Demographics**: 30-45, Data Scientist or AI Engineer.
*   **Bio**: A technical specialist who views agents as modular components. They care about high-fidelity metrics and neural weights.
*   **Goals**: Optimize swarm efficiency, reduce task latency, and ensure architectural DNA integrity during succession.
*   **Motivations**: Efficiency, technical precision, and system stability.
*   **Pain Points**: "Black box" agent behavior, lack of granular control over capability vectors, and manual scaling of agent networks.

### B. The Narrative Designer (Creative Strategist)
*   **Demographics**: 25-35, UX Writer or Creative Director.
*   **Bio**: Focused on the "Soul" of the agents. They use Civitas to build personality-rich assistants for end-user applications.
*   **Goals**: Create distinct, relatable agent personas with consistent voice and tone.
*   **Motivations**: Authenticity, user engagement, and variety in agent archetypes.
*   **Pain Points**: Repetitive agent responses, difficulty in "anchoring" specific persona traits, and sterile system interfaces.

### C. The Operations Manager (Product Owner)
*   **Demographics**: 35-50, Operations Director or PM.
*   **Bio**: Uses the swarm to automate business processes. They treat agents as a digital workforce.
*   **Goals**: Maximize ROI on agent utilization and ensure all job Benchmarks stay "Green."
*   **Motivations**: Cost reduction, throughput, and transparency.
*   **Pain Points**: High idle times for specialized agents, lack of a high-level "Executive Summary" for swarm health.

### D. The Ecosystem Researcher (Academic/Lab)
*   **Demographics**: 22-60, PhD Researcher or Professor.
*   **Bio**: Investigates the emergent behaviors of agent multi-node networks.
*   **Goals**: Map relationship trust networks and observe mutation rates across generations.
*   **Motivations**: Discovery, publishing findings, and pushing the boundaries of AGI behavior.
*   **Pain Points**: Limited visualization of agent-to-agent interactions (Sociometrics) and rigid data export options.

### E. The Hobbyist Curator (Power User)
*   **Demographics**: 18-30, Indie Developer or Tech Enthusiast.
*   **Bio**: Enjoys "breeding" and collecting high-level agents, treating the ecosystem like a high-stakes digital garden.
*   **Goals**: Level up agents to Mastery (LVL 20) to unlock rare succession lineages.
*   **Motivations**: Achievement, community prestige, and curiosity.
*   **Pain Points**: Slow progress tracks, lack of "showcase" features for their best agents.

## 2. Collaboration & Sharing Features

To transition Civitas from a solo tool to an enterprise ecosystem:

### Invite & Workspace Management
*   **Workspace Invites**: Allow owners to invite collaborators via email to specific "Swarms" (groups of agents).
*   **Shared Repositories**: A global "Library" where users can publish agent archetypes for others to clone.

### Granular Permission Levels
*   **Viewer**: Can see agent stats and swarm progress but cannot edit DNA or launch jobs.
*   **Contributor**: Can assign tasks and level up agents but cannot delete core identities or authorize succession.
*   **Admin**: Full control over swarm architecture, permissions, and legacy authorizations.

### Direct Agent Sharing (The "idCard" Link)
*   **Public Profiles**: Generate a unique, read-only URL for a specific agent (idCard) to showcase its capability vector and lineage.
*   **DNA Export**: Export a JSON "DNA Blueprint" that can be imported into a collaborator's workspace.

## 3. Core Feature Roadmap

The foundational pillars for managing the **idCard Personas Swarm**.

### Creation & Initialization
*   **Procedural Generation**: Input a core role, and the system uses Gemini to generate a balanced Capability Vector.
*   **Archetype Inheritance**: New agents can be born from "Core Templates" (Institutional Blueprints).

### Grouping & Categorization
*   **Swarm Collections**: Tag and group idCards into functional units (e.g., "Dev Swarm", "Creative Labs", "Security Tier").
*   **Dynamic Filtering**: Search by level, reputation, trust, or specific dominant capability (e.g., "Show all agents with Coding > 80").

### Analytic Summaries
*   **Ecosystem Pulse**: A real-time dashboard showing global utilization, success rates, and active mutations.
*   **Lineage Mapping**: A tree structure showing the ancestry of every agent in the swarm.

### Interaction & Feedback
*   **Manual Evaluation**: Users can "Upvote" or "Downvote" task outputs to influence an agent's Trust and Reputation scores over time.
